# Measurements

Reproducible checks and dated observations of Pusaq's quota, resilience and
policy behavior. Every report states its protocol, environment and limits.
Results describe the recorded run, not a guarantee for the current checkout
or another deployment. No measurements are regenerated by a documentation edit.

## Run locally

Measurement recipes require Docker Compose, Make, Bash, jq, bc, awk and GNU
date. The Go-only checks require the version in [go.mod](../../go.mod).

| Command | Scope |
|---|---|
| `make test-loadtest` | Deterministic shell verifier fixtures; no Docker or cloud |
| `go test -race ./internal/ratelimit ./internal/gateway` | Limiter, lease, reservation and HTTP regressions with local test doubles |
| `go test -v -run TestContentRulesCorpus ./internal/policy` | Labeled content-rule corpus and precision/recall floors |
| `make loadtest` | Strict RPM through two replicas and a local Redis |
| `make loadtest LOADTEST_MODE=lease` | The same profile with leased RPM |
| `make tpmtest` | Token reservation/reconciliation under emulated provider latency |
| `make breakertest` | Primary-provider failure with a healthy fallback |
| `make chaos-local` | Readiness-injection harness with local round-robin routing |

Load recipes flush the Compose Redis and drain gateway events before
verification. Use the dedicated local stack. Each invocation retains one
`RUN_ID`; artifacts are written under `loadtest/out/`. Stop the profile with
`make loadtest-down`.

`make calibrate` exercises a separate 60-pair seed dataset with the local
embedder. It writes a precision/recall curve and either reports a threshold
meeting the precision floor or exits with an explicit failure. This validates
the harness; it does not establish a production threshold or cache savings.

## Cloud boundary

`make chaos-run` requires the temporary two-region runtime and incurs cloud
charges. Follow [operations](../operations.md#cloud-measurement-environment)
to configure a published image SHA and create/destroy that environment.
Local chaos uses nginx without health-based routing and does not measure
cloud failover time. Readiness injection leaves instances running; it does
not establish survival of a hard regional failure or an in-flight SSE stream.
